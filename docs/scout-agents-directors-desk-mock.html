Why this works — and what it needs

The thinking: the screen's job isn't "browse 809 players by country" — it's "tell me who to act on and why." So the structure is action-first: SIGN NOW calls lead, ranked by the Director's fit score; MONITOR and the long tail are one tap away. Country collapses from a wall of headers into a single line on each card and a filter. The reason to sign is the headline, in the Director's own words.

  • No thumbs. The honest feedback signal is a shortlist add — the skill-learner already trains on shortlistAdds. We stop asking users to rate players they'll never rate.
  • Everything shown is already computed: directorAction, directorVerdict, directorFitScore, directorValueArc, directorDataFlags, matchScore, fmPa/fmCa, contractExpires, and the intel* fields — all written to ScoutProfiles today.
  • Cross-agent corroboration ("found by 2 scouts") is the one new thing — it's detected in scoutAgent.js but only the count is persisted. One small worker change stores the per-player list; a genuinely high-signal badge.
  • One required API change: /api/war-room/scout-profiles must stop dropping the director/intel/stat fields it already reads. The type gains ~10 fields. No pipeline or ML work.
  • Fully consistent with the Alpha Board — same .brit-room tokens (Oswald/Manrope, black + gold), same conic score rings, same right-side dossier drawer pattern, same shortlist callable. Bilingual EN/HE + RTL ready.

If this is the direction, I'll (1) extend the API + type, (2) persist the cross-agent list in the worker, and (3) rebuild WarRoomScoutAgents.tsx as this Director's Desk. Say the word.
